# スキャン画面パターン集(sample/scan)設計

日付: 2026-07-28
ステータス: 設計確定(実装プラン作成前)

## 目的

スキャン画面の典型パターンを `src/sample/scan/` に「パターン集」として整備する。
`*Page.vue` はレイアウト(側/ガワ)だけの薄いコンテナとし、部品とロジックの
組み合わせを変えるだけで呼び出し画面ごとに異なるスキャン画面を構成できることを示す。
実案件へは `src/sample/scan/` ごとコピーして流用できる自己完結モジュールとする。

## 要件

スキャン画面は以下の直交する4軸の組み合わせで構成される。

| 軸 | 選択肢 |
|---|---|
| 読み取り種別 | QR / バーコード / OCR(いずれもカメラプレビュー必須) |
| 読み取りモード | 単発(1件読取で結果へ) / 連続(リストに蓄積) |
| 値の解決 | そのまま返却 / API 連携で DB 照会 |
| 値の加工 | そのまま利用 / 分割して複数項目へ代入(連続時はリストの列にも適用) |

アーキテクチャ要件:

- `.vue` はレイアウトのみ。ロジックは外部 ts(composable / 純関数)に切り出す
- スキャン画面と結果画面は**別ルート**で遷移する(モバイル戻るボタン対応・実案件動線に近い)
- ヘッダとフッタ(ボタンエリア)は場所固定。カメラプレビュー高さも固定
- スキャン画面のリスト表示は件数+直近概要のみ。全リストは結果画面で表示
- 結果画面のリストは**1件=1カードの縦積み**(横スクロール忌避)。カード枚数=件数表現。
  件数バーを上部固定し、カード部のみスクロール

## コンポーネント間連携の方針

**ハイブリッド方式**(検討の結果採用):

- 画面内(ページ ⇔ 部品)は **props/emits**。部品は「値を emit するだけ」で store 非依存
- スキャン画面 ⇄ 結果画面の画面またぎだけ **`scanSessionStore`** を使う
- **store にはシリアライズ可能なデータのみ**入れる(モード・読取値・蓄積リスト)。
  既存 `scannerStore` のようなコールバック関数の保持はしない(リロード破壊・テスト困難の元凶)
- parser / resolver などの戦略(関数)は `logic/` に置き、両画面の logic が **import で共有**する

## ディレクトリ構成(機能モジュール型)

```
src/sample/scan/
├─ pages/          # 側(ガワ)だけの *Page.vue
├─ components/     # 表示部品(props/emits のみ)
├─ logic/          # ロジック ts(composable・純関数)
├─ stores/         # scanSessionStore(データ専用)
└─ types/          # 型定義
```

テストは `src/sample/scan/__tests__/` に配置する。

## logic/(ロジック層)

| ファイル | 責務 |
|---|---|
| `useScanEngine.ts` | 読取エンジンの抽象化。`ScanEngine` インターフェース(start/stop/onResult)。qr/barcode は既存 `@/composables/useBarcodeScanner`(zxing)へ委譲。**OCR はプレビュー+シャッターボタンでダミー文字列を返すスタブ**(実案件で Tesseract 等に差し替え可能な同一インターフェース) |
| `useScanSession.ts` | 読取セッション操作。`single`: 1件読取で停止し結果画面へ / `continuous`: `items[]` へ蓄積・削除・クリア・完了遷移。状態本体は `scanSessionStore` に置き、この composable が読み書きを仲介する |
| `useScanResolve.ts` | 値の解決戦略。`raw`(そのまま)/ `api`(orval 生成の商品 API + vue-query で照会。スキャン値=商品コードとして照会) |
| `parsers.ts` | 値の加工。`passthrough`(そのまま)/ `split`(区切り文字で商品コード・ロット・数量に分割)。純関数でユニットテスト対象 |
| `useXxxPage.ts` | パターンページごとの結線(セッション+resolver+parser の組み合わせ)。ページ vue はこれを import してバインドするだけ |

## stores/

`scanSessionStore`(Pinia setup store):

- state: `mode`(single/continuous)、`scanType`(qr/barcode/ocr)、`rawValue`、`items[]`、`patternId`
- actions: `startSession(config)`、`addItem`、`removeItem`、`clear`、`consumeResult`
- コールバック・関数・Promise は保持しない

## components/(表示部品)

| 部品 | 役割 |
|---|---|
| `ScanCameraView.vue` | カメラプレビュー+エンジン起動/停止+トーチ。OCR 時はシャッターボタン表示。`props: scanType`, `emit: scan`。カメラ権限エラーは内部に表示 |
| `ScanTypeTabs.vue` | QR/バーコード/OCR 切替タブ(`v-model`) |
| `ScanSummaryBar.vue` | スキャン画面用の件数+直近1件の概要表示 |
| `ScanResultCard.vue` | 単発読取結果の表示(値・形式・時刻) |
| `ScanItemList.vue` | 蓄積リスト。**1件=1カードの縦積み形式**(横スクロール忌避のためテーブルは使わない)。表示項目定義(ラベル+キー)を props で受け、raw(読取値/形式/時刻)/分割済み(商品コード/ロット/数量)両対応でカード内に縦にラベル表示。**件数バー(読取済み: n件+クリア)を上部固定・カード部のみスクロール**。カード枚数がそのまま件数表現。行削除 emit |
| `ScanFixedLayout.vue` | 共通レイアウト側。内部で既存 `@/components/layout/SubLayout`(固定ヘッダ+戻る)を使い、フッタ(ボタンエリア)固定+中身スクロールを追加。フッタは slot で各ページが差し込む |

## pages/(パターンページ)

各パターンは「スキャン画面」+「結果画面」の2ルートで構成。すべて薄い側で、
script は対応する `logic/useXxxPage.ts` を呼ぶだけ。

| # | パターン | モード | 加工 | 解決 | 結果画面の内容 |
|---|---|---|---|---|---|
| 1 | single-raw | 単発 | そのまま | そのまま | 結果カード |
| 2 | single-split | 単発 | 分割 | そのまま | 分割フォーム(複数項目へ代入) |
| 3 | single-lookup | 単発 | そのまま | API照会 | 商品詳細カード(loading/error/data 切替) |
| 4 | list-raw | 連続 | そのまま | そのまま | 蓄積リスト(1カラム+時刻) |
| 5 | list-split | 連続 | 分割 | そのまま | 蓄積リスト(分割カラム) |
| — | index | — | — | — | 5パターンへのナビカード一覧 |

「連続+API照会」は部品の組み合わせで実現可能なことが上記で示せるため作らない(YAGNI)。

## ルート

`router/index.ts` に遅延 import で追加:

```
/sample/scan                      → ScanPatternIndexPage
/sample/scan/<pattern>            → 各スキャン画面(例: /sample/scan/single-raw)
/sample/scan/<pattern>/result     → 各結果画面
```

結果画面に直接アクセスされ store が空の場合はスキャン画面へリダイレクトする。

## 画面レイアウト

### スキャン画面(共通骨格)

```
┌─────────────────────────────┐
│ ←  スキャン(タイトル)        │ ◀ ヘッダ固定
├─────────────────────────────┤
│ [ QR ][ バーコード ][ OCR ]   │
│ ┌─────────────────────────┐ │
│ │    カメラプレビュー        │ │ 高さ固定(約40vh)
│ │  (読取枠 + 🔦 / 📷OCR)    │ │
│ └─────────────────────────┘ │
│  読取済み: 3件               │ ◀ 連続時: 件数+直近1件の概要のみ
│  直近: ITEM02 / LOT-B / 5   │    (単発時は読取→即結果画面へ遷移)
├─────────────────────────────┤
│ [ キャンセル ]  [ 読取完了 → ] │ ◀ フッタ固定(連続時のみ読取完了)
└─────────────────────────────┘
```

### 結果画面(連続系)

```
┌─────────────────────────────┐
│ ←  読取結果                  │ ◀ ヘッダ固定
├─────────────────────────────┤
│  読取済み: 3件      [クリア]  │ ◀ 件数バー固定
│ ═══════ ここだけスクロール ═══│
│ ┌─ 1件目 ──────────────── 🗑┐│
│ │ 商品コード: ITEM01        ││ ◀ 1件 = 1カード
│ │ ロット   : LOT-A          ││   項目は縦ラベル表示
│ │ 数量     : 12             ││   (横スクロールなし)
│ └──────────────────────────┘│
│ ┌─ 2件目 ──────────────── 🗑┐│
│ │ ...                      ││
│ └──────────────────────────┘│
├─────────────────────────────┤
│ [ ← 再スキャン ]  [ 確定 ]    │ ◀ フッタ固定
└─────────────────────────────┘
```

list-raw ではカード内が「読取値/形式/時刻」、list-split では「商品コード/ロット/数量」。

### 結果画面(単発系)

中央部がパターンで差し替わる(結果カード / 分割フォーム / API照会詳細)。
フッタは「← 再スキャン」「確定」で固定。

### 動線

- 単発: 読取成功 → 自動で結果画面へ遷移(カメラ停止)
- 連続: カメラ継続でリストへ蓄積 → 「読取完了」で結果画面へ
- 「再スキャン」で スキャン画面へ戻る(連続はリスト保持、単発は破棄)
- 「確定」でセッションを確定し索引(呼び出し元想定)へ戻る
- 同一値の二重読みは既存クールダウン(1.5秒)で抑止

## エラー処理

- カメラ権限エラー: `ScanCameraView` 内に表示(既存 `useBarcodeScanner` の error を流用)
- API 照会失敗: 結果画面内に error 表示(vue-query の isError)+既存 `useSnackbar` で通知
- 結果画面への直接アクセスで store 空: スキャン画面へリダイレクト

## テスト

`src/sample/scan/__tests__/` に vitest で:

1. `parsers.ts` の純関数テスト(passthrough / split / 不正入力)
2. `useScanSession` + `scanSessionStore` のユニットテスト(蓄積・削除・確定・単発遷移)
3. 代表ページのマウントテスト(single-raw と list-split のスキャン画面/結果画面)

カメラ(zxing)はモックする。既存テストの流儀(`@vue/test-utils` + vuetify plugin)に合わせる。

## スコープ外

- OCR の実読取(Tesseract 等) — スタブのみ
- 連続+API照会のページ化
- 既存 `ScannerPage` / `scannerStore` / QuickScan 系のリファクタリング(今回は触らない)
